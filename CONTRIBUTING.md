# Contributing

Thank you for contributing to the Salesforce Learning Platform.

This project is designed as an open learning resource covering Salesforce development, frontend engineering, and enterprise architecture.

## Before You Contribute

Before creating content or making changes:

1. Check existing issues and discussions.
2. Keep content technically accurate and practical.
3. Use official documentation and reliable sources where applicable.
4. Do not copy content from external sources without permission or attribution.
5. Avoid including confidential, proprietary, or client-specific information.

## Content Standards

Learning content should:

- Explain concepts clearly.
- Use practical examples where appropriate.
- Follow current technical best practices.
- Distinguish facts from opinions or recommendations.
- Include relevant prerequisites and learning objectives.
- Be structured for progressive learning.

## Code Standards

Code contributions should:

- Be readable and appropriately documented.
- Follow platform and language conventions.
- Avoid unnecessary complexity.
- Include setup or execution instructions when required.
- Not contain secrets, credentials, or environment-specific information.

## Contribution Process

1. Find or create an issue.
2. Discuss the proposed change when necessary.
3. Create a dedicated branch.
4. Make and test your changes.
5. Open a pull request.
6. Ensure the contribution meets the relevant acceptance criteria.
7. Address review feedback before merging.

## Important

Do not include confidential information from employers, clients, Salesforce organizations, or other private systems.

Examples may be inspired by real-world experience, but proprietary names, data, configurations, architecture, and business logic must not be disclosed.
