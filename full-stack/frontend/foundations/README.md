# Foundations — Start Here

## Purpose

Foundations is the first domain in the [Frontend learning path](../README.md). It has no
prerequisites — if you're new to web development entirely, this is where you begin. Every later
domain (HTML, CSS, JavaScript, and beyond) assumes you're comfortable with the material here:
how the web actually moves data, how client and server responsibilities split, your local dev
environment, and your Git/GitHub workflow.

## Your Learning Path

Work through these in order. Check each box as you finish it — this list is meant to be your
actual progress tracker, not just a table of contents (GitHub renders these as clickable
checkboxes when viewing this file in the repository).

- [ ] [How the Internet Works](how-the-internet-works/) — networks, DNS, TCP/IP, HTTP/HTTPS, and
      the full journey from URL to rendered page
- [ ] [Client-Server Architecture](client-server-architecture/) — frontend vs. backend
      responsibilities and the request-response lifecycle
- [ ] [Internet Protocols](internet-protocols/) — the protocol landscape beyond HTTP
- [ ] [Understanding HTTP and HTTPS](understanding-http-and-https/) — methods, status codes,
      headers, and HTTPS in practice
- [ ] [Preparing Your Machine](preparing-your-machine/) — terminal, Node.js, your editor, browser
      DevTools
- [ ] [Git and GitHub](git-and-github/) — version control and the pull request workflow
- [ ] [AI as Your Coding Partner](ai-as-your-coding-partner/) — using AI tools effectively without
      losing engineering judgment
- [ ] [Reading Documentation](reading-documentation/) — navigating and evaluating technical docs

## When to Deep-Dive vs. Skim

Not every learner needs the same depth everywhere. Use this to calibrate:

| If you... | Then... |
|---|---|
| Have never studied networking before | Read [How the Internet Works](how-the-internet-works/) in full — it's assumed knowledge everywhere else in this platform |
| Already know Git well from prior experience | Skim [Git and GitHub](git-and-github/), but still verify you can explain merge conflicts and the PR workflow's *why*, not just its steps |
| Have never used an AI coding assistant | Read [AI as Your Coding Partner](ai-as-your-coding-partner/) in full before using one on real project work |
| Are comfortable with a terminal and package managers already | Skim [Preparing Your Machine](preparing-your-machine/), but confirm your editor has linting and format-on-save configured |
| Struggle to debug a "connection failed" vs. a "404" error | Deep-dive [How the Internet Works](how-the-internet-works/) and [Understanding HTTP and HTTPS](understanding-http-and-https/) together before moving on |
