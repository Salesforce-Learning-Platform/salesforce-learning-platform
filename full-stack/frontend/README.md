## The Learning Path, in Order

The domains below build directly on each other. Working through them in this order means every
module can assume what came before it, instead of re-explaining prerequisites — this is what
makes learning here fast and non-repetitive.

```text
1. Foundations              → how the web actually works, your tools, your workflow
2. HTML                     → structuring content
3. CSS                      → styling and layout
4. JavaScript               → behavior and interactivity
5. TypeScript                → typed JavaScript at scale
6. React                    → building UI with components
7. Next.js                  → production React applications
8. Frontend Architecture     → reading and navigating real, larger codebases
```

## If You Already Know Some of This

Each domain's own entry point lists its prerequisites explicitly. If you're already comfortable
with, say, JavaScript fundamentals, it's reasonable to start at CSS or jump straight to
JavaScript's more advanced topics — just make sure you can genuinely answer the "Knowledge Check"
questions in a module's files before skipping it, not just that the topic sounds familiar.

## How to Read a Module

Every module in this platform follows the same shape, so once you know it, you can navigate any of
them:

- **A `README.md`** — the module's overview: purpose, learning objectives, prerequisites, and a
  table of its files in reading order.
- **Individual concept files** — each covers one focused idea, ending with a "Next" pointer to the
  file that continues the sequence.
- **Knowledge-check questions** (`<details>` blocks you can click to reveal the answer) — use these
  to self-test before moving on, not just to read passively.
