# Setting Up SCSS

## Installing the Sass Compiler

```bash
npm install --save-dev sass
```

Sass is a build-time tool — it belongs in `devDependencies`
(per [npm-and-package-management.md](../../../backend/starting-with-nodejs/npm-and-package-management.md)'s
distinction), since nothing about the running application needs it once the CSS has already been
compiled.

## Compiling SCSS to CSS

```bash
npx sass src/styles/main.scss dist/styles/main.css
```

```json
{
  "scripts": {
    "build:css": "sass src/styles/main.scss dist/styles/main.css",
    "watch:css": "sass --watch src/styles/main.scss dist/styles/main.css"
  }
}
```

The Sass CLI takes a source `.scss` file and an output `.css` path. `--watch` keeps the compiler
running, automatically recompiling every time the source file changes — the practical way to work
with Sass during active development, rather than manually re-running the compile command after
every edit.

## Build Tool Integration

```js
// vite.config.js — Vite (and most modern bundlers) compile .scss files
// automatically, with zero extra configuration beyond having `sass` installed
export default {
  // importing a .scss file directly just works
};
```

In practice, most real projects don't invoke the Sass CLI directly — a bundler like Vite (already
used throughout [the React domain](../../react/introduction-to-react/)) detects a `.scss` import
and compiles it automatically as part of the normal build process, as long as the `sass` package is
installed. This is why installing the compiler is usually the only setup step actually needed.

## Source Maps for Debugging

```bash
npx sass --source-map src/styles/main.scss dist/styles/main.css
```

A **source map** (the same underlying idea covered for JavaScript bundling in
[asset-loading-strategy.md](../../performance/frontend-performance-fundamentals/asset-loading-strategy.md)'s
broader performance context) lets browser DevTools show the original `.scss` source and line
numbers when inspecting a compiled style, rather than the generated CSS — genuinely useful once a
project has more than a trivial number of Sass files.

## Common Mistakes

- Installing `sass` as a regular `dependency` instead of a `devDependency` — it's only ever needed
  at build time, never by the running application itself.
- Manually re-running the compile command after every edit instead of using `--watch` (or relying
  on a bundler's built-in Sass support) during active development.
- Committing the *compiled* `.css` output to version control alongside the `.scss` source — the
  compiled output should generally be regenerated by the build process, not tracked as if it were
  hand-written.
