# Project-Based Learning Framework

## Purpose

This document defines the conceptual framework for integrating practical, project-based learning into the Salesforce Learning Platform.

Projects provide learners with opportunities to apply knowledge across multiple concepts rather than demonstrating understanding only through individual lessons or assessments.

The framework establishes how projects can function as part of a broader learning experience without defining a specific technical project management or submission system.

---

## Project-Based Learning Principles

Project-based learning should focus on meaningful application of knowledge.

The framework is based on the following principles:

- Projects should have clear learning objectives.
- Practical work should align with the concepts being learned.
- Projects should encourage the application of multiple skills where appropriate.
- Complexity should be suitable for the learner's level.
- Project outcomes should be understandable and measurable.
- Projects should complement learning content rather than replace foundational instruction.
- Practical learning should progressively increase in complexity.

---

## Role of Projects

Projects may serve different purposes within the learning platform.

They can be used to:

- Reinforce concepts introduced in learning modules.
- Combine knowledge from multiple topics.
- Provide practical implementation experience.
- Prepare learners for more complex technical challenges.
- Validate the application of knowledge.
- Create portfolio or demonstration work where appropriate.

A project does not need to represent a complete production system. Its scope should remain aligned with the intended learning outcomes.

---

## Project Structure

A project may be organized into several conceptual components.

### Project Overview

The overview should explain the purpose of the project and the expected outcome.

It may include:

- Project objective
- Target learner level
- Required knowledge
- Expected deliverables
- Estimated scope

---

### Prerequisites

Projects may require learners to understand specific concepts before beginning.

Prerequisites can include:

- Foundational modules
- Technical concepts
- Previous exercises
- Related projects
- Required platform knowledge

Prerequisites should be identified clearly where they affect the learner's ability to complete the project.

---

### Requirements

Project requirements define what the learner is expected to build, configure, analyze, or complete.

Requirements should provide sufficient direction without necessarily prescribing every implementation decision.

Depending on the learning objective, projects may include:

- Functional requirements
- Technical constraints
- Required technologies
- Expected behaviors
- Acceptance criteria

---

### Milestones

Larger projects may be divided into milestones.

Milestones provide a structured way to divide complex work into meaningful stages.

For example:

1. Project setup
2. Core implementation
3. Feature development
4. Testing and validation
5. Final review

The exact milestone structure should depend on the nature of the project.

---

### Deliverables

A project may require one or more deliverables that demonstrate completion.

Examples include:

- Source code
- Configuration
- Documentation
- Screenshots
- Technical explanations
- Demonstrations
- Completed exercises

Deliverables should remain relevant to the learning objectives.

---

## Project Difficulty Levels

Projects may be organized according to increasing levels of complexity.

### Foundational Projects

Foundational projects focus on applying a limited set of concepts within a guided structure.

Learners may receive detailed instructions and clearly defined implementation steps.

### Intermediate Projects

Intermediate projects require learners to combine multiple concepts and make some implementation decisions independently.

Guidance may be provided, but learners should have greater responsibility for completing the solution.

### Advanced Projects

Advanced projects may involve broader requirements, problem-solving, technical decision-making, and the integration of multiple skills.

The learner may be expected to determine a significant portion of the implementation approach.

Difficulty should reflect the learning path and the knowledge expected at each stage.

---

## Project Guidance

The level of guidance should be appropriate for the learning objective.

Guidance may include:

- Project instructions
- Recommended implementation steps
- Reference material
- Examples
- Hints
- Validation criteria

As learner proficiency increases, projects may provide less prescriptive guidance and require greater independent problem-solving.

The goal is to gradually transition learners from guided implementation toward independent application.

---

## Project Validation

Projects may be validated using different approaches depending on the nature of the work.

Potential validation methods include:

- Defined acceptance criteria
- Automated checks
- Manual review
- Functional testing
- Code review
- Self-assessment
- Demonstration of expected behavior

The platform does not currently define a mandatory validation method.

Validation should remain proportionate to the complexity and learning importance of the project.

---

## Relationship to Assessments

Projects can provide a form of practical knowledge validation.

Unlike traditional assessments, projects may evaluate the learner's ability to combine concepts and apply them within a broader context.

A project may therefore complement:

- Knowledge checks
- Module assessments
- Practical exercises
- Path-level assessments

Project completion and project mastery should remain conceptually distinct unless future validation requirements define them as equivalent.

---

## Project Progress

Learner progress within a project may eventually be tracked through milestones, activities, or deliverables.

Potential progress states may include:

- Not Started
- In Progress
- Submitted
- Requires Review
- Completed

The exact tracking mechanism is outside the scope of this framework.

Project progress should remain consistent with the broader Learner Progress Tracking Model.

---

## Relationship to Learning Paths

Projects may appear at different points within a learning path.

For example:

**Foundational Learning → Guided Exercise → Intermediate Project → Advanced Project**

Projects should be placed where learners have sufficient knowledge to attempt the required work.

Project outcomes may also help learners identify readiness for more advanced learning content.

---

## Project Maintenance

Projects may require updates when related technologies, platforms, or learning content change.

Maintenance may include:

- Updating requirements
- Correcting outdated instructions
- Replacing deprecated technologies
- Updating examples
- Revising validation criteria
- Adjusting prerequisites

Major project changes should consider the impact on related learning paths and learner progress.

---

## Future Evolution

As the Salesforce Learning Platform evolves, project-based learning may later support capabilities such as:

- Project templates
- Starter repositories
- Automated environment setup
- Automated validation
- Project submissions
- Peer review
- Mentor feedback
- Portfolio integration
- Project analytics

These capabilities are not required at the current stage.

This document establishes the conceptual foundation for using practical projects as part of the learning experience within the Salesforce Learning Platform.
